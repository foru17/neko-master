# 代理节点名称合并

部分订阅会在节点名称后附加剩余流量或到期时间。网关上报的名称随之变化，
流量统计就会被拆到多个节点条目中。

打开 **设置 → 偏好设置 → 代理节点名称合并**，选择采集后端，添加匹配规则：

| 字段 | 示例 |
| --- | --- |
| 匹配方式 | 名称以此开头 |
| 原始名称或名称前缀 | `美国节点 01 - 剩余流量：` |
| 合并后的固定名称 | `美国节点 01` |

这样，`美国节点 01 - 剩余流量：50GB` 和 `美国节点 01 - 剩余流量：25GB`
会合并为 `美国节点 01`。匹配条件中应保留节点编号和订阅标识；
`美国` 这样的宽泛前缀会合并所有匹配的节点。
如果只想把某个旧名称归到固定别名，可使用“名称完全一致”。
多个不同的匹配条件可以使用同一个别名。

## 工作方式

- 规则只作用于选中的采集后端，默认没有规则，维持原有统计行为。
- 完整名称匹配优先；没有完整匹配时，选择最长的名称前缀。
- 按字面匹配，区分大小写，不支持正则或通配符。前缀中的空格有意义，尾部空格也会参与匹配。
- 节点排行榜、节点的域名/IP 明细、域名/IP 的节点流量分布都会合并历史和实时流量。
  时间范围和明细数量限制在合并后的数据上生效。
- 仅对代理链的第一个节点应用别名，其他跳点、策略组、网关配置和规则流图保留原名，
  保证网关策略匹配与节点选择正常工作。
- 不改写原始流量记录，保存后无需重启采集器，不修改 Agent 协议。
  删除规则即可恢复分开统计，包括规则生效期间采集的流量。
- 清空统计数据会保留规则；删除采集后端时，会同时删除它的规则。

每个后端最多 50 条规则。匹配条件和别名须为 1–256 个字符，
不含控制字符或代理链分隔符（` > `）。别名不能包含 `>` 或带首尾空格，
也不能被另一条规则继续改名。不能匹配或使用 `DIRECT`、`REJECT` 等内置名称作为别名。

规则存储在现有 SQLite `app_config` 表中，即使统计查询使用 ClickHouse 也是如此。
无需数据库迁移。

## API

读取：`GET /api/db/proxy-name-aliases?backendId=1`

保存：`PUT /api/db/proxy-name-aliases`

```json
{
  "backendId": 1,
  "rules": [
    { "match": "prefix", "value": "美国节点 01 - 剩余流量：", "alias": "美国节点 01" }
  ]
}
```

响应格式为 `{ "rules": [...] }`。传入空数组可移除此后端的全部合并规则。
接口使用现有认证机制，展示模式下禁止修改。
